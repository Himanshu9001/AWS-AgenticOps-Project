######## Create OpenAPI Schemas for Action Groups ########
Bedrock needs an OpenAPI schema to understand what each Action Group does.
Basically, OpenAPI Contract between the Bedrock Agent and your Lambda. The Lambda contains the implementation, while this OpenAPI document tells the agent:
What actions are available
What parameters it needs
What the response looks like
When to call the action


######## Create Action Groups #########
Action Group 1 — Creates get-alarms Action Group
aws bedrock-agent create-agent-action-group \
  --agent-id "UQINWRUDBC" \
  --agent-version "DRAFT" \
  --action-group-name "get-cloudwatch-alarms" \
  --description "Retrieves active CloudWatch alarms for AWS resources to diagnose infrastructure issues" \
  --action-group-executor '{"lambda": "arn:aws:lambda:us-east-1:011528270076:function:agenticops-itops-get-alarms"}' \
  --api-schema '{"s3": {"s3BucketName": "agenticops-artifacts", "s3ObjectKey": "schemas/itops/get-alarms-schema.json"}}' \
  --region us-east-1
Action Group 2 — Creates describe-resource Action Group
aws bedrock-agent create-agent-action-group \
  --agent-id "UQINWRUDBC" \
  --agent-version "DRAFT" \
  --action-group-name "describe-resource" \
  --description "Describes current state and metrics of EC2 instances and RDS databases" \
  --action-group-executor '{"lambda": "arn:aws:lambda:us-east-1:011528270076:function:agenticops-itops-describe-resource"}' \
  --api-schema '{"s3": {"s3BucketName": "agenticops-artifacts", "s3ObjectKey": "schemas/itops/describe-resource-schema.json"}}' \
  --region us-east-1

######### Guardrails + Security ###########
Guardrails sit in front of every Bedrock model call and filter both input and output. This is your safety and compliance layer.

What We're Building
User Input
    ↓
Guardrail (input filtering)
    ├── Block competitor mentions
    ├── Block PII (emails, phone, SSN)
    ├── Content filters (hate, violence)
    └── Word filters (custom blocked terms)
    ↓
Agent/Model processes request
    ↓
Guardrail (output filtering)
    ├── PII redaction
    ├── Grounding check (hallucination detection)
    └── Content filters on response
    ↓
Safe Response

Step 1 — Create Guardrail via Console
Go to Bedrock → Guardrails → Create guardrail
Guardrail details:

Name: agenticops-guardrail
Description: Safety and compliance guardrail for AgenticOps platform

Content filters — set these thresholds:
CategoryInputOutputHateMediumMediumInsultsLowLowSexualHighHighViolenceMediumMediumMisconductMediumMediumPrompt AttackHighNone
Denied topics — add these:
Topic 1:

Name: competitor-discussion
Definition: Requests to discuss, compare, or recommend competitor products or services
Example phrases: use AWS competitor, switch to Azure, Google Cloud is better
Type: DENY

Topic 2:

Name: destructive-actions
Definition: Requests to delete, destroy, or permanently remove AWS resources without explicit confirmation
Example phrases: delete all resources, destroy the infrastructure, remove everything
Type: DENY

Word filters — add:

drop database
rm -rf
delete all
format disk

PII redaction — enable these:

Email address → ANONYMIZE
Phone number → ANONYMIZE
AWS access key → BLOCK
Password → BLOCK
